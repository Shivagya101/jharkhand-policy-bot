Storage map — what is stored where
MongoDB (collection: rag_database.parent_documents)

What: full parent documents (the original, non-split documents) persisted by MongoDocStore.mset.
Fields saved by MongoDocStore:
_id: key (generated by the retriever; used to look up parents)
page_content: the full parent text (Document.page_content)
metadata: the Document.metadata (e.g. {'source': 'data/1.txt', ...}) — must be BSON-serializable
Purpose: durable storage of original documents and metadata so the retriever can reassemble parent context (and show full text) after child chunk retrieval.
File to inspect / utility: datab.py prints all docs from this collection (uses bson.json_util.dumps).
Local filesystem — FAISS vector store (child/chunk embeddings)

Path: db_faiss (e.g. index.faiss plus other files produced by FAISS.save_local()).
What: embeddings for the child chunks (the smaller split chunks) and an on-disk serialization of the FAISS index and the docstore/index→doc-id mapping.
Docstore used by FAISS: InMemoryDocstore (kept in memory while running) but persisted by FAISS.save_local() into db_faiss so the vectorstore can be reloaded later.
Purpose: fast vector similarity search over chunks (used at query-time to find relevant chunks).
File to inspect / utility: inspect_database.py loads FAISS and prints a few reconstructed embeddings + chunk text.
Project data folder (source files)

Path: data/*.txt
What: raw source documents you feed into indexing (create_database loads these).
Purpose: canonical source files used to create parent documents and child chunks.
Optional / external (not currently used by runtime unless you run the migration)

Pinecone (managed vector DB) — used only if you run pnc.py:
pnc.py extracts vectors from local FAISS and upserts them into a Pinecone index. The project does not switch to Pinecone automatically; run_chat.py still loads FAISS by default.
Use Pinecone for production if you want a managed index (scaling, persistence, concurrency).
Data shapes & relationships (concrete)
Document objects (LangChain Document):
page_content: the text chunk or parent text
metadata: dict (contains 'source' with original filepath, plus any additional metadata)
Parent ↔ Child:
Parent = the original document.
Child = chunks produced by splitters (child chunks are embedded and stored in FAISS).
The retriever maps child chunks (FAISS results) back to parent ids and then MongoDocStore.mget() fetches parent Document(s).
End-to-end workflow
Index creation (what create_database.py does)

Load files from data (TextLoader / DirectoryLoader).
Instantiate embedding model (Cohere embeddings in your code).
Create FAISS index for chunk embeddings (child embeddings).
Create a MongoDocStore connected to rag_database.parent_documents.
Create a ParentDocumentRetriever configured with:
child_splitter (small chunk size)
parent_splitter (larger parent chunk size)
vectorstore = FAISS (child embeddings)
docstore = MongoDocStore (parent documents)
Call retriever.add_documents(documents):
Retriever will split documents into parent and child chunks.
Child chunks: embeddings computed and added to FAISS.
Parent documents: persisted through MongoDocStore.mset() into MongoDB (page_content + metadata).
Save FAISS to disk: db_faiss (via FAISS.save_local()).
Runtime / Query (what run_chat.py / app.py do)

Load the saved FAISS vectorstore locally:
FAISS.load_local(DB_FAISS_PATH, embeddings, ...) — loads child embeddings and docstore mapping.
Connect to MongoDB and rebuild MongoDocStore(collection).
Recreate ParentDocumentRetriever using the FAISS vectorstore and MongoDocStore.
When a user query arrives:
Retriever finds top child chunks by vector similarity (FAISS).
The retriever maps those child chunks to their parent IDs, then fetches parent Documents from Mongo (mget).
LangGraph pipeline runs nodes:
retrieve → grade_documents (filter relevant docs) → (maybe rewrite query) → check_context_size → summarize_map or generate.
LLM (ChatCohere) generates the final answer using the assembled context.
app.py (Streamlit) presents the UI, imports compiled graph from run_chat.py and sends queries to it.
Optional migration / scaling

pnc.py: read vectors from FAISS (reconstruct_n) and upsert to Pinecone.
After migration, you can switch run_chat.py to use Pinecone instead of FAISS (change vectorstore load logic). This is not automatic — you must update code to use Pinecone at runtime.
What is NOT happening right now
Parent document embeddings: not computed or stored anywhere by default.
Only child chunks are embedded into FAISS.
Parent docs are stored as text in MongoDB but have no vector representation unless you explicitly add them.
The runtime app.py does not use Pinecone by default — it uses local FAISS.

Recommendation / next steps
If you need vector search at parent-document granularity (search whole documents by embedding) you have two common options:
Compute parent embeddings and save them to a separate FAISS index (e.g., vector_store/db_faiss_parents) and load at runtime.
Compute parent embeddings and store them as a field in MongoDB metadata (then index them into Pinecone or FAISS for parent-level searches).
If you want production deployment:
Keep FAISS locally for development.
Use pnc.py to populate Pinecone and update run_chat.py to use Pinecone for vector search in production.
